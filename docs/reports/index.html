fast-ecc — experiment reports

The measurements behind the changes in yosh-shimizu/fast-ecc.

Reducing the warps per iterationlanded

How three bilinear warps per iteration become one. The chain rule lets the gradients be taken after the warp and mapped back with A⁻ᵀ, so the two gradient warps disappear.

The warp reduction against the border fix, and re-tuning gaussFiltSizelanded

Whether the two changes compose without harming each other, and what the optimal blur width is once the border defect no longer penalises wide filters. Identifies OpenCV's threading asymmetry as the reason the warp reduction stops paying at large windows — on a single thread it is flat at 1.27–1.31× across the whole range. Also establishes that this fork's apparent accuracy advantage was an accident of gaussFiltSize=5.

Fusing the Gauss–Newton stagemeasured, not yet committed

Building the Hessian and the projections in one pass, without ever materialising the Jacobian. Shows that all four motion types are a column subset of the same face-splitting product u ⊗ w, and that the saving grows with the parameter count — 2.47× for homography at window 768 on four threads.

These reports reference the measuring harness under eval/, which lives in a separate working tree and is not part of this repository; reproducing the figures needs it. What is reproducible from here is ./build/bench and ctest.

Measured on an Intel Core i7-8700K (6C/12T), Windows 11, MSVC, Release, against OpenCV 4.15.0-dev built with the border fix applied.
Every speed figure carries a motion type, a window size and a thread count. A ratio without all three does not mean anything in this code.
