ECC 高速化テクニックの解説

「反復あたりの幾何ワープを 3 → 1 に削減する」最適化の仕組みと数学的根拠
対象: OpenCV cv::findTransformECC（Forward-Additive ECC）／ 参考実装 ref/ecc.cpp

1. 要約

核心

3 → 1

反復あたりの幾何ワープ（warpAffine / warpPerspective）回数を削減。勾配を「ワープ後画像の filter2D」で得る。

なぜ速い

warp ≫ conv

双線形ワープは座標変換+4タップ補間/画素。homography は毎画素除算も。これを安い conv+addWeighted に置換。

正しさ

A·Aᵀ

連鎖律の係数を addWeighted で戻す。translation/euclidean は厳密、affine/homography は正定値前処理（収束保存）。

ECC は ρ(p)=⟨îr, iw(p)⟩ / ‖iw(p)‖ を反復最大化する。各反復で必要なのは (a) ワープ後画像 iw と (b) パラメータヤコビアン用の勾配 ∇I(W(x)) の2つ。 高速化の鍵は (b) の入手方法を変えることにある。

2. 何を変えたか

2.1 オリジナル（OpenCV）— 毎反復で勾配を「幾何ワープ」

ループ前に入力画像の勾配 ∇I を一度だけ計算し、毎反復で画像・勾配x・勾配y・マスクの計4枚（うち画像系3枚）を幾何ワープする。

// ループ前: 入力全体で勾配を1回計算（filter2D）
filter2D(imageFloat, gradientX, -1, dx);
filter2D(imageFloat, gradientY, -1, dx.t());

// 毎反復: 3枚を幾何ワープ（高コスト）
warpAffine(imageFloat, imageWarped,     map, ...);  // 画像
warpAffine(gradientX,  gradientXWarped, map, ...);  // 勾配x  ← 重い
warpAffine(gradientY,  gradientYWarped, map, ...);  // 勾配y  ← 重い
warpAffine(preMask,    imageMask,       map, ...);  // マスク

2.2 参考実装 — 画像だけワープし、勾配は「ワープ後に作る」

幾何ワープは画像1枚＋マスクのみ。勾配はワープ後画像を filter2D で微分し、warp の線形係数で addWeighted 再合成する。

// 毎反復: 幾何ワープは画像1枚だけ
warpAffine(imageFloat, imageWarped, map, ...);          // 画像（1枚だけ！）
warpAffine(preMask,    imageMask,   map, ...);            // マスク

// ワープ後画像から勾配を作る（安い）
filter2D(imageWarped, imageWarpedGradientX, -1, dx);     // 1×3 分離conv
filter2D(imageWarped, imageWarpedGradientY, -1, dx.t());

// 連鎖律の係数を画素ごとに戻す（安い）
warp_gradients_affine_ECC(imageWarpedGradientX, imageWarpedGradientY,
                          map, gradientXWarped, gradientYWarped);
//  └ 中身: addWeighted(gx, a, gy, b, 0, outX);  // a*gx + b*gy
//          addWeighted(gx, c, gy, d, 0, outY);  // c*gx + d*gy

ループ前の勾配プリ計算（gradientX/gradientY）は不要になり撤去。参考実装で残る同名の宣言は使われない残骸。

3. なぜ速いか（コスト比較）

反復あたりの主処理オリジナル参考実装
幾何ワープ（画像系, 双線形）3 回1 回
filter2D（1×3 分離）0 回2 回
addWeighted（画素線形結合）0 回2 回
マスクのワープ（最近傍）1 回1 回

双線形 warpAffine は「逆変換の座標計算＋4タップ補間＋境界判定」を画素ごとに行う。 warpPerspective はさらに毎画素の射影除算を伴う。一方 filter2D(1×3) と addWeighted は画素あたり数回の積和のみ。重いワープ2回を軽い演算に置換するため、特に homography で効果が大きい。

反復あたりの「画像系・幾何ワープ」回数（少ないほど速い）

削減されるのは最もコストの高い処理。homography では除算付き warpPerspective が 2 回消える。

4. 数学的根拠 — なぜ成立するか

ワープ後画像は iw(x) = I(A·x + t)（A は map の 2×2 線形部、WARP_INVERSE_MAP）。 これを filter2D で空間微分すると、連鎖律で勾配にヤコビアン因子が掛かる:

∂x[ I(A·x + t) ] = Aᵀ · ∇I(W(x)) （filter2D が返す生の勾配 g̃ = Aᵀ ∇I）

ECC のヤコビアン式が必要とするのは生の ∇I(W(x))。そこで warp_gradients_*_ECC が A を掛けて戻す（addWeighted）。結果は A·g̃ = A·Aᵀ·∇I となる。

モーション線形部 AA·Aᵀ結果
translationI（単位）I厳密一致
euclideanR（回転=直交）I厳密一致
affine一般 2×2≠ I（対称正定値）近似（前処理子）
homography一般（射影）≠ I（対称正定値）近似（前処理子）

translation / euclidean

厳密

A が単位/直交なので A·Aᵀ=I。オリジナルと完全に同一のヤコビアンを、ワープ2回分の節約で得る。

affine / homography

近似

A·Aᵀ 因子が残るが、これは対称正定値＝プリコンディショナとして作用。上昇方向は保たれ、 ステップ→0 の不動点も実質不変。「正しさを損なわず」ワープを削減できる。

5. 付随する工夫と注意点

5.1 境界処理は速度化トリックの「対」

ワープ後画像を filter2D すると、有効領域とゼロ埋め境界の境目で勾配が汚染される （オリジナルは「計算済み勾配をワープ」していたので無問題だった）。そのため参考実装は マスクの 2 画素縁をゼロ化し、汚染勾配を破棄している。これは高速化に伴い必要になった正しさの補正。

preMask.row(0..1).setTo(0);  preMask.row(末尾0..1).setTo(0);   // 2px縁を無効化
imageWarpedGradientX.setTo(0, 1 - imageMask);                  // 縁の勾配を捨てる

6. 結論

高速化の正体は、毎反復の勾配を「∇I を幾何ワープして得る」代わりに、「ワープ後画像を filter2D し連鎖律係数を addWeighted で戻して得る」こと。 これにより反復あたりの画像系・幾何ワープを 3 → 1 に削減する。

  • translation / euclidean では厳密に等価、affine / homography では正定値前処理として作用する近似で収束は保たれる。
  • 効果は warpPerspective に毎画素除算がある homography で最大。
  • ワープ後微分に伴う境界汚染の除去（2px 縁マスク）が必須の対であり、デバッグ出力は本番で除く。
